# TradePulse Pro — Render Staging Environment Variables Specification

## 1. Environment Variables Overview

The staging service (`tradepulse-pro-staging`) operates in production mode (`NODE_ENV=production`) for strict cookie and header security, but connects exclusively to the Neon development branch (`tradepulse-dev`).

---

## 2. Staging Environment Matrix

Configure these values in the Render dashboard for `tradepulse-pro-staging` under **Environment**:

| Variable Name | Staging Setting / Value | Purpose | Source / Security Rule |
| :--- | :--- | :--- | :--- |
| `NODE_ENV` | `production` | Enforces HTTPS-only cookies (`Secure`), `SameSite=Strict`, Express `trust proxy: 1`, and sanitized error outputs. | Declared in `render.staging.yaml`. |
| `APP_ENV` | `staging` | Distinguishes telemetry and staging runtime status from production. | Declared in `render.staging.yaml`. |
| `PORT` | `10000` | Port assigned by Render for inbound routing; bound to `0.0.0.0` by server. | Declared in `render.staging.yaml`. |
| `DATABASE_URL` | Pooled URI for `tradepulse-dev` | Prisma query pooling and `connect-pg-simple` session store. | **Obtained from Neon Console -> Project `quiet-dawn-96765050` -> Branch `tradepulse-dev` -> Pooled Connection**. |
| `DIRECT_URL` | Direct URI for `tradepulse-dev` | Direct database connection for Prisma operations. | **Obtained from Neon Console -> Branch `tradepulse-dev` -> Direct Connection**. |
| `SESSION_SECRET` | Auto-generated 64-char string | Cryptographic key used to sign session cookies. | **Auto-generated by Render via `generateValue: true`**. |
| `FINNHUB_API_KEY`| User's Finnhub API Key | Real-time and cached market data ingestion. | Configured manually in Render dashboard. |

> [!CAUTION]
> **Database Isolation Checklist:**
> 1. Double check that the hostname in `DATABASE_URL` matches the `tradepulse-dev` compute endpoint (`ep-wild-pond-b56aiy9j-pooler.c-7.us-east-2.aws.neon.tech`).
> 2. Never use `ep-ancient-glade` (the production compute endpoint) in staging.
> 3. Never prefix secrets with `VITE_` to ensure zero client-bundle exposure.

---

## 3. Render Free Tier Idle & Sleeping Notice

- **Spin-Down Window**: The staging service spins down after 15 minutes of inactivity.
- **WebSocket & Background Alerts**: Streaming subscriptions and continuous alert monitoring will pause during idle spin-down. Active trading and price threshold evaluations resume as soon as the service receives traffic and wakes up.
